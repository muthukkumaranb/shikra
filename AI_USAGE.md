# AI Assistance Disclosure

This document discloses the AI tools used during the development of SHIKRA, the scope of their contributions, the independent verification mechanisms applied to their outputs, and the strict rules observed.

---

## 1. AI Tools Used

The engineering workflow incorporated multiple AI systems for design critique, rapid prototyping, and automated implementation:

- **Planning & Verification Assistant**: Claude (Anthropic) used for specification drafting, design critique, evaluation protocol definition, and adversarial review.
- **Coding Agents & Assistants**:
  - **Antigravity**: Agentic pair-programming assistant used for full-lifecycle implementation, verification runs, test harness execution, and documentation authoring.
  - **GitHub Copilot**: In-editor completion and commit-level assistance during feature implementation and refactoring.
  - **Claude Code**: Terminal-based coding agent for automated test execution, lint resolution, and script scaffolding.

## 2. What AI Did & Quality Control Process

- **Code, Test, and Documentation Drafting**: AI agents drafted code modules, unit/integration test suites, and technical documentation strictly following the team's specifications and issue descriptions.
- **Independent Re-Verification Protocol**: No AI-generated output was merged based on agent assertion alone. Every contribution was independently re-verified:
  - Clean environment execution of the entire test suite (`pytest -q -m "not data"`).
  - Clean environment re-execution of data pipelines and simulation runs (`make reproduce-sim-quick` / `scripts/check_reproduce.py`).
  - Continuous Integration (GitHub Actions) validation running on independent runners before any merge to `main`. As defined in `.github/workflows/ci.yml` and `.github/workflows/reproduce-full.yml`, CI executes:
    - Lint check: `ruff check .`
    - Test execution: `pytest -q -m "not data"`
    - Quick simulation reproduction: `make reproduce-sim-quick PY=python`
    - Bitwise result verification: `python scripts/check_reproduce.py --quick`
    - Full reproduction on push to `main`: `make reproduce-sim PY=python` and `python scripts/check_reproduce.py`
- **Observed Failure Types Caught and Corrected**:
  - Agents reported "ruff clean" while CI failed on lint (UP038), three times.
  - A CP-SAT benchmark ran a heuristic while labelled as the CP-SAT solver; caught in review, replaced with the real OR-Tools solver.
  - A README claimed a dependency version (torch==2.2.2) that was not in requirements.txt.
  - A README overstated what the quick verify script covers (it skips the supply-shock run).
  - Streamlit SVG output rendered as a code block / blank in headless Chromium; caught by rendering every page in a real browser before merge.
  - A failing test was pushed because a PowerShell block ran git push after pytest failed; fixed next commit; the merge procedure now checks pytest before pushing.

## 3. Strict Engineering Rules Followed

1. **Zero Competitor or Proprietary Code**: No third-party proprietary software, competitor intellectual property, or confidential internal frameworks were used, ingested, or referenced.
2. **Public and Synthetic Data Only**: Strictly limited to publicly available NASA C-MAPSS turbofan degradation datasets and synthetically generated squadron maintenance logs; zero access to or use of real operational aircraft maintenance records.
3. **No Typed Result Numbers**: Result numbers in README.md are generated by scripts/readme_table.py from committed CSVs; runtimes are approximate measurements.
